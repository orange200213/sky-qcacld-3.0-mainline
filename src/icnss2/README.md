# MiCode sky ICNSS2 Adrastea source port

Source: https://github.com/MiCode/Xiaomi_Kernel_OpenSource/tree/9adb4dca796fbc465bca5731feed21641f87bd2b
Branch: sky-t-oss, kernel commit 9adb4dca796fbc465bca5731feed21641f87bd2b
WLAN source pairing: vendor_qcom_opensource_wlan sky-t-oss commit 02e10575f1357db03d74b9d59a1edd3a88614181.

`include/soc/qcom/icnss2.h` is the stock ABI used by qcacld PLD/SNOC. The original platform implementation lives under `drivers/soc/qcom/icnss2/`; the pinned CNSS utilities and WLFW/DMS QMI encoding sources are staged alongside it. Headers for downstream-only APIs are present for compiler analysis, not as implementations. Source files are being ported; the original files are no longer all byte-for-byte copies.

From this directory, run `make -f port.mk dependencies` first, then `make -f port.mk wlan`. The first target cross-builds the authentic `cnss_utils.ko` and `wlan_firmware_service.ko` and their exported symbol versions; the second builds `icnss2.ko` and links the paired qcacld `wlan.ko` against its real exports. Override `KERNEL_SRC`, `WLAN_DIR`, `ARCH`, and `CROSS_COMPILE` as needed. The target kernel's configured build tree and `Module.symvers` must exist. Current source-only ARM64 builds pass modpost for both dependency modules, the ICNSS2 module, and the WLAN module. `modinfo` reports `wlan` depending on `icnss2` and `icnss2` depending on `wlan_firmware_service` (not on `cnss_utils`).

The Adrastea build only matches `qcom,icnss`; WCN6750/WCN6450 are intentionally excluded because their Android remoteproc recovery hook has no verified mainline replacement. Sky's stock Adrastea node includes `wpss-support-enable`, so WPSS SSR is required. Mainline has one WPSS `BEFORE_SHUTDOWN` notifier chain, not the original independent early-SSR chain: the original early `FW_DOWN` and QMI timeout flag operations now run at the start of the normal WPSS shutdown callback. This is a real notification but **not timing-equivalent** to the vendor early callback; restart/timeout ordering needs device validation. The missing downstream `socinfo_get_serial_number()` is replaced by the same SMEM item 137 access used by the target kernel's `socinfo.c`; a missing or too-short item returns zero, as qcacld requires for MAC fallback failure. The IIO consumer namespace is explicitly imported.

Compilation and modpost do **not** establish a usable device driver. The target board file `sky-linux/dts/sm4450-xiaomi-sky.dts` now has an enabled `qcom,icnss` node with the stock 8 MiB membase, twelve CE IRQs, 12 MiB fixed MSA, WPSS remoteproc and SMP2P phandles, and IOMMU stream ID. An offline Linux 7.3 cpp/dtc build succeeds and the decoded DTB contains these resources; this board file is separate from the kernel tree's generic `sm4450-qrd.dts`. The stock ch1 supply has no verified board rail here, and the existing board supply mappings have not been runtime verified. `tools/mksky_dts.py` still generates the previous WCN/ath11k WLAN node, but now refuses to overwrite the ICNSS2 board file; compare only through `SKY_DTS_OUTPUT` until its other board-file drift is audited. The fixed MSA `memremap()` now has a device-managed `memunmap()` action on probe failure or remove. The ramdump minor/class allocation now unwinds if msa0 creation or WPSS notifier registration fails, and remove tolerates recovery-disabled instances without a ramdump class. The fixed MSA mapping, QMI lookup failure, sysfs failure, DMS-before-WLFW initialization, notifier/timer shutdown, event workqueue, WPSS loader and WPSS rproc reference paths now have explicit source-level cleanup. Failed `rproc_boot()` no longer leaves a stale pointer, and remove releases any retained WPSS rproc reference after cancelling its work. The local firmware backup contains the Adrastea WPSS image set (`wpss.mdt`, `wpss.mbn`, `wpss.b00` through `wpss.b10`) and board-data files; this is an inventory check only, not a firmware test or installation. The Linux 7.3 monitor-channel callback was minimally updated for its `struct net_device *` argument. The remaining qcacld cfg80211 callback type mismatches are numerous independent API-generation differences and remain outside this driver-only pass; the qcacld Kbuild still suppresses them with `-Wno-error` and they must not be treated as runtime ABI proof. Source-only compile cannot validate firmware transactions, DT resources or the changed SSR timing; global work/notifier interactions and all vendor failure paths still need device-side validation. Do not install, load, or flash any of these modules yet.
